# Temperature Sensor & Midea Fan Control

Embedded system project using **STM32F103C8T6 (Blue Pill)** to measure temperature with an **LM35** sensor, display the temperature on an **ST7735 TFT LCD**, and automatically control a **Midea fan** through infrared (IR) signals.

## Features

- Measure ambient temperature using LM35
- Display temperature on ST7735 TFT LCD
- Generate IR carrier signal using TIM3
- Receive and analyze IR signals using TIM4
- Decode Midea IR protocol
- Transmit Midea IR commands to control the fan
- Automatically control fan power, mode, and speed based on temperature

---

## Components

- **STM32F103C8T6 Blue Pill**
- **ST7735 TFT LCD 128×160** — SPI interface
- **LM35** — analog temperature sensor
- **IR transmitter module** — for transmitting control signals to the Midea fan
- **IR receiver module** — for receiving and analyzing IR remote-control signals

---

## System Overview

The system consists of three main functions:

1. **Temperature sensing**
   - LM35 provides an analog voltage proportional to temperature.
   - STM32 reads the voltage using ADC1.

2. **Display**
   - The measured temperature is displayed on the ST7735 TFT LCD through SPI1.

3. **Fan control**
   - The STM32 determines the required fan state from the measured temperature.
   - Midea IR commands are transmitted using an IR carrier generated by TIM3.

The IR protocol was first captured from the original Midea remote control and analyzed to reproduce the required commands.

# Peripheral Configuration

## ADC1

ADC1 is used to read the analog output of the LM35 temperature sensor.

- Channel: `ADC1_IN0`
- Pin: `PA0`
- Conversion mode: Single conversion
- Trigger: Software
- Sampling time: `239.5 cycles`
- ADC calibration: Performed at startup

The temperature is sampled multiple times and averaged before being used by the control logic.

The current implementation takes **10 ADC samples** and calculates the average value before applying the temperature conversion.

---

## TIM3 — IR Carrier

TIM3 Channel 1 generates the carrier signal used by the IR transmitter.

- Channel: `TIM3_CH1`
- Pin: `PB0`
- Prescaler: `0`
- Period: `1730`
- PWM mode: `PWM1`
- Output polarity: High

The system clock is configured at **64 MHz**.

TIM3 is connected to APB1. Because APB1 uses a prescaler of 2, the STM32 timer clock is still:

```text
64 MHz
```

Therefore, the PWM frequency is approximately:

```text
f = 64 MHz / (1730 + 1)

  ≈ 36.97 kHz
```

So the IR carrier frequency is approximately:

```text
≈ 37 kHz
```

The PWM carrier is enabled only when an IR command is being transmitted.

---

## TIM4 — IR Signal Timing

TIM4 is used as a timing counter for IR signal reception and protocol analysis.

Configuration:

- Prescaler: `63`
- Period: `65535`
- Counter mode: Up
- Clock source: Internal

With a timer clock of 64 MHz:

```text
64 MHz / (63 + 1)
= 1 MHz
```

Therefore:

```text
1 timer tick = 1 µs
```

The maximum counter value is:

```text
65535 µs
```

and the overflow period is approximately:

```text
65.536 ms
```

This provides microsecond-level timing resolution for measuring the pulse widths and spaces of the Midea IR protocol.

---

## SPI1 — TFT Display

SPI1 is used to communicate with the ST7735 TFT LCD.

Configuration:

- Mode: `Master`
- Direction: `Transmit Only`
- Data size: `8-bit`
- Clock polarity: Low
- Clock phase: 1st edge
- First bit: MSB
- Baud rate prescaler: `4`
- Software NSS
- CRC: Disabled

The APB2 clock is 64 MHz.

With a prescaler of 4:

```text
64 MHz / 4
= 16 MHz
```

Therefore, the SPI clock is:

```text
16 MHz
```

SPI1 pins are remapped to:

```text
PB4 — SCK
PB5 — MOSI
```

# Midea IR Control

The fan is controlled by reproducing the infrared commands sent by the original Midea remote control.

The control process consists of:

1. Capturing the IR signal from the original remote.
2. Measuring the timing of the signal.
3. Decoding the transmitted data.
4. Identifying the commands corresponding to different fan states.
5. Reconstructing the IR frame.
6. Transmitting the frame using the STM32 IR transmitter.

The IR carrier generated by TIM3 is approximately **37 kHz**.

---

## Automatic Fan Control

The fan state is determined from the measured temperature.

| Temperature | Fan state |
|---|---|
| `< 23°C` | OFF |
| `23°C – < 25°C` | ON + Silent |
| `≥ 25°C` | ON + Normal |

When the fan is operating in **Normal** mode, the fan speed is selected according to temperature:

| Temperature | Fan speed |
|---|---|
| `< 28°C` | Speed 1 |
| `28°C – < 32°C` | Speed 2 |
| `≥ 32°C` | Speed 3 |

Therefore, the control behavior can be summarized as:

```text
Temperature < 23°C
        │
        ▼
      OFF

23°C ≤ Temperature < 25°C
        │
        ▼
   ON + Silent

Temperature ≥ 25°C
        │
        ▼
   ON + Normal
        │
        ├── < 28°C  → Speed 1
        │
        ├── < 32°C  → Speed 2
        │
        └── ≥ 32°C  → Speed 3
```

---

## State Tracking

The software keeps track of the current fan state to avoid repeatedly transmitting the same IR command.

The control logic tracks:

- Power state
- Silent / Normal mode
- Current fan speed
- Previous fan speed

An IR command is transmitted when a required state changes.

For example, if the temperature remains within the same temperature range, the STM32 does not continuously resend the same command.

The implementation behaves as a state machine even though the states are represented using variables rather than an explicit `enum`.

Conceptually, the states are:

```text
OFF
 │
 └── ON + Silent

ON + Normal
 ├── Speed 1
 ├── Speed 2
 └── Speed 3
```

---

# Important Startup Requirement

The Midea fan does not provide feedback to the STM32 about its current state.

The STM32 therefore cannot know the actual fan state when the system starts.

Before starting the automatic control system, the fan should be manually configured to the following initial state:

```text
Power  : OFF
Mode   : Normal
Speed  : 1
```

This provides a known starting state so that the software's internal state matches the actual state of the fan.

> The STM32 assumes that the fan starts from this known state. If the actual fan state is different, the software's internal state may not match the physical fan state.

# Temperature Measurement

The LM35 produces an analog voltage proportional to temperature.

The sensor output is connected to:

```text
LM35 OUT → PA0 (ADC1_IN0)
```

The ADC performs multiple measurements and averages them to reduce measurement noise.

Current implementation:

```text
10 ADC samples
        │
        ▼
    Average
        │
        ▼
 Temperature
```

The resulting temperature is then used by both:

- TFT display
- Automatic fan control

# IR Transmission Process

The IR transmitter uses the following mechanism:

```text
STM32
  │
  ├── TIM3
  │     └── ~37 kHz PWM carrier
  │
  ▼
IR transmitter
  │
  ▼
Midea fan IR receiver
```

During transmission, the software controls whether the carrier is present according to the decoded Midea IR protocol.

The protocol consists of timed carrier bursts and pauses. TIM3 generates the carrier while the software controls the duration of each burst and space.

---

# IR Signal Analysis

The original Midea remote control was used to capture the IR signal.

The captured waveform was analyzed by measuring:

- Pulse durations
- Space durations
- Header sequence
- Data bits
- Frame structure
- Repeated portions of the transmission

TIM4 provides a `1 µs` timing resolution, allowing the waveform to be analyzed at microsecond precision.

The decoded data is then used to construct the IR transmission frame.

# Notes

- The fan control relies on transmitting valid Midea IR frames.
- The STM32 does not receive feedback from the fan.
- The fan must therefore start from a known state.
- IR transmission distance and reliability depend on the IR transmitter module, transmitter orientation, receiver sensitivity, and environmental conditions.
- The IR carrier used by this project is approximately 37 kHz.
- The project currently uses polling for ADC temperature measurement.
